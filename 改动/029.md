ai修复情况:
已按 029 需求补齐本轮实现，核心处理如下：

1. 需求自动执行开关
   - 总需求新增 `autoExecuteFlag` 字段，页面显示为“自动执行”开关，默认关闭。
   - 客户端上线、心跳恢复、默认会话创建完成后，不再无条件自动推进所有工作流任务。
   - 自动恢复执行时只处理 `autoExecuteFlag=true` 的工作流总需求。
   - 手动点击“从头开始执行”仍可正常下发当前工作流就绪节点，不受自动执行开关限制。

2. 推送通知区分
   - 子模块状态开始/完成仍使用 `STARTED` / `FINISHED`。
   - 执行标识创建/释放改为 `EXECUTION_MARKED` / `EXECUTION_CLEARED`，不再和完成状态混在同一类动作里。
   - 前端右下角通知继续只提示真正的“开始执行”和“执行完成”，执行标识变化只用于页面自动刷新和状态锁定。

3. 后端统一 MCP 文件检索 API
   - 新增 `POST /api/mcp/agents/{agentCode}/files`。
   - 新增 `GET /api/mcp/agents/{agentCode}/tools`，MCP 关闭时返回空工具列表。
   - 调用时必须带 Agent 编号，服务端会查找当前在线且已关联该 Agent 的客户端。
   - 服务端通过 WebSocket 向客户端下发 `MCP_FILE_REQUEST`，客户端执行后通过 `/api/mcp/client-requests/{requestId}/complete` 回填结果。
   - 当前支持操作：
     - `TREE`：返回目录树。
     - `LIST`：返回指定目录下一层文件。
     - `READ`：读取文件内容。
     - `SEARCH`：按文件名或内容模糊搜索。

4. Python 客户端 MCP 文件服务
   - `client-config.json` 新增 `mcp` 配置：
     - `enabled`：是否启用 MCP 文件检索。
     - `server_url`：MCP 服务地址说明配置。
     - `max_file_bytes`：单文件读取最大字节数。
     - `max_entries`：目录/搜索最大返回数量。
   - MCP 关闭时接口仍然能走通，但客户端返回 `enabled=false`，不返回文件数据。
   - 文件访问被限制在对应 Agent 的 `workspace_dir` 内，防止通过路径穿越读取工作目录之外的文件。
   - 搜索和目录树默认跳过 `.git`、`node_modules`、`dist`、`target`、`__pycache__` 等目录。

5. 项目和需求配置
   - 项目新增“可用 MCP 文件检索 Agent”配置，页面支持多选，也支持手工输入 Agent 编号。
   - 新建总需求时会默认引用项目里的 MCP 文件检索 Agent 列表，并允许在需求层覆盖。
   - 总需求详情展示自动执行状态和 MCP 检索 Agent。
   - 子模块新增“启用 MCP 文件检索”开关，默认关闭。
   - 工作流模式的弹窗创建/编辑子模块时也支持配置 MCP 文件检索。

6. 任务下发提示词
   - 如果子模块启用了 MCP 文件检索，服务端下发给 Agent 的提示词会附带：
     - MCP 文件检索 API 调用方式。
     - 工具列表接口和文件调用接口。
     - 可用 Agent 编号。
     - 当前在线客户端、项目和工作目录信息。
     - 支持的 `TREE/LIST/READ/SEARCH` 操作说明。
   - 未启用 MCP 文件检索的子模块不会额外注入这段内容。
