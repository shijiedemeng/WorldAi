需求改动:
   项目管理 新增基础md历史记录，只针对基础类型的md
   作用是，项目有一个配置，是否在客户端启动(初始化acp之前)的时候自动同步或更新基础md文件
   客户端连接的时候，因为会有配置关联了哪些项目，找到这些项目，看一下这个配置，目前选项有 独立 / 自动更新   另外一个选项 是否允许自动上传版本比服务器当前高的
   第一个作用是就是看需不需要同步或者各自独立，第二个就是如果允许自动更新的时候，就得看一下版本问题，如果高于版本，那么看配置，如果允许覆盖，那么需要上传，而且把旧版本放到历史版本管理里，方便随时回滚，回滚需要更新版本号，避免陷入死循环
   另外 Agent 信息 需要新增一个选项，就是当前Agent 信息对应的智能体是什么？选项有codex，qoder，claude
   同时你需要更新[ai-api-agent-integration](../skills/ai-api-agent-integration) 这个技能，就是创建或者或者对应的Agent的时候，需要带上智能体信息，但是选项只给codex，qoder，claude，避免胡乱回答
   这次改动比较大，你好好处理
ai修复情况:
   已新增项目基础 MD 同步配置：
   - 项目配置新增 baseMarkdownSyncMode，支持 独立(INDEPENDENT) / 自动更新(AUTO_UPDATE)。
   - 项目配置新增 baseMarkdownAllowClientUpload，用于控制客户端本地基础 MD 版本高于服务端时是否允许自动上传覆盖服务端。
   - 保留原 markdownSyncMode 作为额外 MD 的冲突处理策略，避免和基础 MD 的独立/自动更新语义混在一起。

   已新增基础 MD 版本和历史记录：
   - project_markdown_file 新增 version_no、last_sync_source。
   - 新增 project_markdown_file_history，只记录基础类型 BASE 的历史版本。
   - 服务端编辑基础 MD、删除基础 MD、客户端上传高版本、回滚前都会把旧版本写入历史表。
   - 回滚会生成新的版本号，版本号取当前版本和历史版本的最大值再 +1，避免客户端再次同步时陷入版本回退循环。

   已新增后端接口：
   - GET /api/projects/{projectCode}/markdown-files/{fileId}/history 查看基础 MD 历史版本。
   - POST /api/projects/{projectCode}/markdown-files/{fileId}/rollback/{historyId} 回滚基础 MD。
   - POST /api/projects/{projectCode}/markdown-files/base-upload 客户端上传本地高版本基础 MD。

   已调整 python-client：
   - 客户端启动并注册成功后，会根据服务端实际关联的 Agent 找到 projectCode，并同步这些项目的基础 MD。
   - 创建 ACP 会话前会再次按 Agent 所属项目同步基础 MD，确保在初始化 ACP 之前完成基础 MD 更新。
   - 本地新增 .ai-api-md-versions.json 记录基础 MD 版本和内容 hash，用于判断本地文件是否被修改。
   - 当项目是自动更新且允许客户端上传时，本地基础 MD 内容高于服务端会自动上传；服务端会保留旧版本。
   - 当项目是独立模式时，基础 MD 不会被客户端自动覆盖或上传。

   已调整前端页面：
   - 项目编辑页新增“基础 MD 同步”和“允许客户端上传”配置。
   - 项目列表新增基础 MD 同步策略展示。
   - 项目 MD 管理页新增基础 MD 同步策略、客户端高版本上传开关、额外 MD 冲突策略。
   - 基础 MD 列表新增版本号展示。
   - 基础 MD 操作新增“历史”，可查看历史内容并回滚。

   已新增 Agent 智能体类型：
   - 后端 AgentInfo 新增 agentEngineType，枚举只允许 CODEX / QODER / CLAUDE。
   - Agent 新建/编辑页新增“智能体”下拉，选项为 codex、qoder、claude。
   - Agent 列表新增智能体类型展示。
   - 客户端在线 Agent 响应中也返回 agentEngineType。

   已更新 ai-api-agent-integration 技能：
   - skill-config.json 新增 agentEngineType。
   - init / agents ensure 支持 --agent-engine-type CODEX|QODER|CLAUDE。
   - SKILL.md 明确创建或对齐 Agent 时必须带智能体类型，只允许 codex/qoder/claude 三类，避免把模型或供应商名称误填进去。

   - 当前环境没有 mvn 命令，也没有 Maven wrapper，后端未能在本机执行 Maven 编译。
