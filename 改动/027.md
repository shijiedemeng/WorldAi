ai修复情况:
已按“正常模式不变，工作流模式下子模块就是流程节点”的方式重做，不再使用节点模式，也不再把 `sortNo` 当作运行时推进规则。

1. 后端工作流数据模型：
   - 新增 `RequirementExecutionMode`：`NORMAL` / `WORKFLOW`。
   - `requirement_info` 新增 `execution_mode`、`result_extractable_flag`，老数据默认正常模式、回执可提取。
   - 新增 `requirement_workflow_edge` 表，用 `from_requirement_no -> to_requirement_no` 表达子模块之间的前置和下一步关系。
   - 工作流只允许关联当前总需求下面的子模块，保存时校验不能为空、不能指向自己、不能跨需求、不能形成循环依赖。

2. 工作流编排接口：
   - 新增 `GET /api/requirements/{requirementNo}/workflow`，返回根需求、节点、流程边、起点节点和当前就绪节点。
   - 新增 `PUT /api/requirements/{requirementNo}/workflow`，保存子模块之间的流程边。
   - 没有前置边的子模块就是起点；同一时间满足前置条件的多个子模块就是并行节点。

3. 工作流执行推进：
   - `POST /api/requirements/{requirementNo}/workflow/dispatch-ready` 不再按 `sortNo` 批次推进，而是查询所有“前置节点已完成且当前状态为 PENDING/BLOCKED”的就绪子模块。
   - 子模块完成后，后端会重新计算后继节点的前置条件；只有全部前置完成的节点才会自动下发。
   - 如果多个节点同时就绪，会一起下发，形成并行执行；如果只有一个节点就绪，就是串行执行。
   - 没有在线 Agent 或默认会话未就绪时不会丢任务；客户端注册、心跳、默认会话创建完成后会再次尝试下发就绪节点。
   - 工作流任务下发时立即标记子模块为 `IN_PROGRESS`，避免重复执行；正常模式仍保持原有执行逻辑。

4. 工作流结果接口：
   - 保留 `GET /api/requirements/{requirementNo}/workflow-results`。
   - 只返回已完成/已关闭且 `resultExtractableFlag=true` 的子模块回执。
   - 返回子模块编号、标题、Agent、需求状态、链路 ID、链路状态、结果摘要、执行回执、交付路径和完成时间，供后续工作流节点读取上游结果。

5. AI 拆分：
   - AI 仍只负责分析子模块，不生成开发链路。
   - Prompt 让 AI 判断 `executionMode=NORMAL|WORKFLOW`。
   - 子模块字段保留 `sortNo`、`resultExtractable`；其中 `sortNo` 只用于 AI 拆分后自动生成默认流程边，运行时不再直接按 `sortNo` 推进。
   - 自动生成规则：较小 `sortNo` 的子模块指向下一层 `sortNo` 的子模块，同层节点表示并行候选。

6. 前端页面：
   - 正常模式下子模块列表保持原逻辑。
   - 工作流模式下，总需求详情页改为基于 `@vue-flow/core` 的“工作流编排”画布，不再显示普通子模块表。
   - 每个子模块就是一个 Vue Flow 节点，节点显示状态、Agent、前置、下一步、是否就绪、回执是否可提取。
   - 通过拖拽节点右侧连接点到另一个节点左侧，建立“当前子模块完成后 -> 下一步执行”的流程边。
   - 画布右侧展示当前流程关系列表，支持删除关系；点击“保存流程”后写回后端。
   - 工作流模式下“新建子模块”入口放在画布工具栏，也支持右键画布空白处快速打开创建弹窗，创建后直接出现在画布中。
   - 子模块创建时继承当前总需求执行模式，不再展示执行模式选择。
   - 页面只保留“从头开始执行”按钮，调用后端自动从当前断点位置下发所有就绪节点，不再提供节点级“单独执行”。
   - 节点编辑改为当前页面弹窗，不再打开单独编辑页签。

7. ai-api-agent-integration 技能：
   - `requirements list` 支持 `--open-only` 和 `--agent-code`，用于查询当前项目/Agent 未完成需求。
   - `requirements workflow-results --requirement-no xxx` 用于执行工作流节点前读取已完成上游回执。
   - 创建/更新需求命令支持 `--execution-mode`、`--result-extractable-flag`。
   - 技能文档已明确：回执只写回 ai-api，不在本地生成 `receipt.md` 或 `receipt_*.md`。
