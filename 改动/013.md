ai修复情况:
1. 已纠正 WebSocket 实现缺口：原来客户端注册时只是上报了 `connectionProtocol=WEBSOCKET` 字段，页面能看到协议标识，但 python-client 并没有真正建立 WebSocket 连接。现在已新增真实 WebSocket 通道：
   - 后端新增 `/ws/clients`。
   - python-client 启动注册后会连接 `/ws/clients` 并发送 `REGISTER clientCode`。
   - 服务端下发执行命令时优先通过 WebSocket 推送 `EXECUTE_COMMAND`。
   - python-client 仍保留 pending 命令轮询作为兜底，避免 WebSocket 断线导致任务丢失。
2. 后端新增运行态客户端执行能力，数据不落库：
   - 客户端会话列表、新增会话、设置默认会话。
   - 执行命令创建、pending 查询、开始执行、完成回传。
   - 命令完成后会根据结果自动回写关联开发链路为 `DONE` 或 `BLOCKED`。
3. 在线客户端页面已新增会话管理：
   - 在客户端详情里查看会话记录。
   - 支持新增会话。
   - 支持设置默认会话。
   - 会话是内存态，服务端重启会丢失，符合当前需求。
4. 需求详情页已新增“执行”按钮：
   - 弹窗展示当前需求/子模块链路关联的在线 Agent。
   - 只展示当前在线客户端已经关联的 Agent。
   - 点击“任务详情”后展示任务信息、默认会话和下发 prompt。
   - 点击“下发”后调用服务端执行下发接口。
5. python-client 已新增执行命令处理：
   - `api.py` 增加 pending/start/complete 命令接口。
   - `command_runner.py` 负责拉取命令、初始化技能、执行 CLI、回传结果。
   - 启动后心跳循环会处理 pending 命令，WebSocket 收到命令也会立即执行。
   - 执行前会在 Agent 配置的 `workspace_dir` 下初始化：
     - `project-markdown-workspace load`
     - `ai-api-agent-integration config show`
   - CLI 默认执行方式为 `<worker_command> -p "<prompt>"`，同时支持 `worker_command` 中使用 `{prompt}` 占位符。
6. ACP 目录已封装接口：
   - 新增 `cli_tools/acp/base.py`，定义 `AcpClient`、`AcpSession`、`AcpPromptResult`。
   - 重写 `qodercli_acp.py` 为无顶层副作用的 `QoderAcpClient`，import 时不会再直接启动进程或打印。
   - `cli_tools/acp/__init__.py` 统一导出，后续接入 codex/claude ACP 可以按同一接口扩展。
7. 当前版本说明：
   - ACP 初始化/默认会话接口结构已经有了，qoder ACP client 已封装，但执行下发当前仍默认走 `worker_command -p`，后续可把 `sessionType=ACP` 接到具体 ACP client。
   - prompt 模版目前由前端下发时生成，内容要求先加载 `project-markdown-workspace` 和 `ai-api-agent-integration`，后续可以再改成服务端动态模版配置。
8. 已验证：
   - 前端 `npm run build` 通过。
   - python-client `compileall` 通过。
   - `--print-runtimes` 正常。
   - Java 编译未能本机验证，因为当前环境没有 `mvn` 命令。

补充修正:
1. 已修正会话编号设计错误：
   - 前端不再要求手工设置会话编号。
   - 后端不再伪造 `SES-...` 作为会话编号。
   - 新增会话时，后端只生成内部 `requestId` 并通过 WebSocket 下发 `CREATE_SESSION`。
   - python-client 在本机创建会话后回填 `sessionId`，页面展示的是这个回填 ID。
2. 已新增会话创建回填链路：
   - 后端新增 pending-create 查询和 complete 回填接口，WebSocket 不通时 python-client 轮询兜底。
   - `ClientAgentSessionResponse` 增加 `requestId`、`sessionId`、`errorMessage`。
   - 需求详情下发任务时使用 `sessionId`，只允许选择 `READY` 的会话。
3. 已接入 python-client 本机会话创建：
   - `sessionType=ACP` 时走 qoder ACP client，创建真实 ACP session 并回填 ACP 返回的 `sessionId`。
   - `sessionType=CLI_PROMPT` 时由 python-client 创建本机运行态会话 ID，避免服务端伪造编号，也不需要页面手工输入。
   - ACP client 会复用，不会每次重复初始化。
4. 已修正在线客户端心跳方式：
   - 页面移除手动“心跳”按钮。
   - WebSocket 注册后服务端按 15 秒自动刷新在线心跳。
   - WebSocket 断开时服务端会将客户端从在线列表移除。
   - python-client 不再在主循环里依赖 HTTP 心跳，HTTP pending 轮询仅作为兜底。
