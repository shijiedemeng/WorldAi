# AI API 前端设计说明（Vue 一期）

## 1. 目标

在现有 `ai-api` 后端一期能力基础上，补一个 **Vue 前端管理台**，与后端放在同一项目目录中，作为多 Agent 协同平台的操作界面。

前端一期目标不是做复杂大而全平台，而是先把核心闭环可视化：

- 项目查看与创建
- 需求查看与创建
- 需求链路任务查看、创建、更新
- Agent 查看、注册、心跳更新
- 测试记录查看、登记
- 主控 inspection 检查结果展示
- Agent 待办任务查看

---

## 3. 页面设计

## 3.1 总体布局

采用后台管理台布局：

- 左侧菜单
- 顶部栏
- 主内容区

### 左侧菜单建议

- 仪表盘
- 项目管理
- 需求管理
- Agent 管理
- 测试记录
- 需求检查

---

## 3.2 仪表盘页面

路径：`/dashboard`

### 展示内容

- 项目数量
- 需求数量
- 处理中需求数量
- 阻塞需求数量
- 在线 Agent 数量
- 待处理链路任务数量

### 一期实现方式

一期可以先通过多个列表接口做前端聚合统计，不强制后端新增 dashboard 专用接口。

---

## 3.3 项目管理

### 3.3.1 项目列表页

路径：`/projects`

展示字段：

- 项目编码
- 项目名称
- 项目状态
- 主控 Agent
- 技术栈
- 更新时间

操作：

- 新建项目
- 查看详情（一期可简化为抽屉/详情页）
- 管理项目 Markdown 配置

### 3.3.2 新建项目页

路径：`/projects/create`

表单字段：

- projectCode
- projectName
- projectDesc
- businessGoal
- techStack
- repositoryUrl
- ownerAgentCode
- markdownSyncMode
- status

对应接口：

- `POST /api/projects`

### 3.3.3 项目 Markdown 管理页

路径：`/projects/:projectCode/markdowns`

展示内容：

- Markdown 同步策略
- 基础 Markdown 文件编辑区
- 额外 Markdown 文件列表

支持操作：

- 切换 `OVERWRITE` / `CANCEL`
- 编辑基础文件内容
- 新增额外 Markdown 文件
- 删除额外 Markdown 文件
- 保存整个项目 Markdown 配置

对应接口：

- `GET /api/projects/{projectCode}/markdown-config`
- `PUT /api/projects/{projectCode}/markdown-config`

---

## 3.4 需求管理

### 3.4.1 需求列表页

路径：`/requirements`

筛选条件：

- projectCode
- status
- requirementNo
- title

展示字段：

- 需求编号
- 标题
- 所属项目
- 优先级
- 当前状态
- 当前阶段
- 主控 Agent
- 更新时间

操作：

- 新建需求
- 查看详情
- 更新状态
- 查看 inspection

### 3.4.2 新建需求页

路径：`/requirements/create`

表单字段：

- requirementNo
- projectCode
- title
- requirementDesc
- priority
- status
- source
- mainAgentCode
- currentStage
- expectedDeadline
- createdBy

接口：

- `POST /api/requirements`

### 3.4.3 需求详情页

路径：`/requirements/:requirementNo`

页面分区：

1. 基本信息
2. 开发链路列表
3. 测试记录列表
4. inspection 结果摘要

本页支持操作：

- 新增链路任务
- 更新链路进度
- 新增测试记录
- 跳转 inspection 详情

需要调用接口：

- `GET /api/requirements/{requirementNo}`
- `GET /api/requirements/{requirementNo}/links`
- `GET /api/requirements/{requirementNo}/tests`
- `GET /api/requirements/{requirementNo}/inspection`
- `POST /api/requirements/{requirementNo}/links`
- `POST /api/requirements/{requirementNo}/tests`
- `PUT /api/links/{linkId}/progress`

## 5. API 封装建议

按模块拆分：

- `src/api/project.ts`
- `src/api/requirement.ts`
- `src/api/agent.ts`
- `src/api/link.ts`
- `src/api/testRecord.ts`
- `src/api/inspection.ts`

统一 Axios 实例：

- baseURL：`/api`
- 超时：10s
- 响应统一解包 `{ code, message, data }`

## 6. 交互要求

## 6.1 通用要求

- 列表页支持 loading
- 请求失败支持 message 提示
- 空列表显示 Empty 状态
- 表单提交有校验
- 状态字段统一用颜色 Tag 表达

## 6.2 状态颜色建议

### RequirementStatus
- `PENDING`：灰
- `IN_PROGRESS`：蓝
- `TESTING`：橙
- `BLOCKED`：红
- `DONE`：绿
- `CLOSED`：深灰

### LinkStatus
- `TODO`：灰
- `DOING`：蓝
- `DONE`：绿
- `BLOCKED`：红
- `SKIPPED`：黄

### AgentStatus
- `ONLINE`：绿
- `OFFLINE`：灰
- `DISABLED`：红

### TestResult
- `PASS`：绿
- `FAIL`：红
- `BLOCKED`：橙

## 8. 目录放置要求

前端与后端放一起，但前后端目录边界清晰：

- 后端：`ai-api/src/main/java`、`src/main/resources`
- 前端：`ai-api/frontend`

后续如需联调，可考虑：

- 开发环境：Vite 代理 `/api` 到 Spring Boot
- 生产环境：前端打包产物再接入后端静态资源或独立部署

---

## 9. 给 ai-api 的实现要求

请按以下顺序开发：

1. 初始化 `frontend` Vue 3 + Vite + TS 项目
2. 接入 Element Plus、Vue Router、Pinia、Axios
3. 完成通用布局和菜单
4. 先完成项目、需求、Agent 三大页面
5. 补需求详情页（链路、测试、inspection）
6. 打通所有现有后端接口
7. 输出前端启动方式和目录说明

---

## 10. 一期验收标准

满足以下条件即视为前端一期达标：

1. 可以打开前端首页
2. 可以查看项目列表并新建项目
3. 可以查看需求列表并新建需求
4. 可以进入需求详情查看链路、测试、inspection
5. 可以新增链路任务并更新进度
6. 可以新增测试记录
7. 可以查看 Agent 列表并注册 Agent
8. 可以查看指定 Agent 待办任务
9. 前端调用当前后端 API 正常返回
10. 项目目录结构清晰，能本地启动
