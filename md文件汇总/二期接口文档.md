# AI API 二期接口文档（草案）

## 1. 项目概览

### 1.1 二期目标

二期在一期接口基础上新增以下能力：

- 项目 Markdown 文件列表化管理
- 总需求 / 子需求树形模型
- Agent 会话管理与会话复用
- 客户端节点接入与本机 Agent 能力上报
- 服务端主动派发任务
- Markdown 同步冲突追踪
- WebSocket 长连接消息协议

### 1.2 技术形态

二期接口分两类：

1. HTTP 接口
   - 管理端、前端、服务端内部查询使用
2. WebSocket 消息协议
   - Python 客户端与服务端长连接通信使用

### 1.3 HTTP 统一返回结构

所有 HTTP 接口统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 1.4 WebSocket 消息封装建议

二期通信层建议使用 **WebSocket 文本帧 + JSON** ，不再使用裸 TCP 自定义分包协议。

连接地址建议：

- 开发环境：`ws://localhost:8080/ws/clients/connect`
- 生产环境：`wss://your-host/ws/clients/connect`

消息统一结构：

```json
{
  "messageId": "msg-20260507-0001",
  "messageType": "CLIENT_REGISTER",
  "clientCode": "client-mac-mini-01",
  "timestamp": "2026-05-07T21:00:00",
  "payload": {}
}
```

说明：

- `messageId` 用于幂等与追踪
- `messageType` 用于路由消息处理器
- `clientCode` 对客户端消息必填
- `payload` 为具体业务内容
- WebSocket 连接层使用 `ping/pong`
- 业务层保留 `CLIENT_HEARTBEAT`

## 2. 模块划分

### 2.1 Project Markdown 模块

负责项目 Markdown 文件列表、同步策略、冲突记录。

### 2.2 Requirement Hierarchy 模块

负责总需求、子需求、需求树和状态聚合。

### 2.3 Session 模块

负责 Agent 会话管理、会话绑定、会话复用查询。

### 2.4 Client Node 模块

负责客户端注册、心跳、本机 Agent 能力上报。

### 2.5 Dispatch 模块

负责服务端主动派发任务、记录执行状态和结果。

### 2.6 WebSocket Gateway 模块

负责服务端与 Python 客户端之间的 WebSocket 长连接消息协议。

## 3. 接口清单

## 3.1 项目 Markdown 管理

### 3.1.1 查询项目 Markdown 聚合配置

- 方法：`GET`
- 路径：`/api/projects/{projectCode}/markdown-config`

说明：

- 保留一期聚合接口，便于兼容
- 返回项目默认同步策略和全部 Markdown 文件

核心响应字段：

- `projectCode`
- `markdownSyncMode`
- `markdownFiles`

### 3.1.2 查询项目 Markdown 文件列表

- 方法：`GET`
- 路径：`/api/projects/{projectCode}/markdown-files`

核心响应字段：

- 文件列表数组
- 每项包含：
  - `id`
  - `fileType`
  - `baseKey`
  - `filePath`
  - `syncEnabledFlag`
  - `displayOrder`
  - `updatedAt`

### 3.1.3 新增项目 Markdown 文件

- 方法：`POST`
- 路径：`/api/projects/{projectCode}/markdown-files`

核心请求字段：

- `fileType`，必填
- `baseKey`
- `filePath`，必填
- `content`，必填
- `syncEnabledFlag`
- `displayOrder`

请求示例：

```json
{
  "fileType": "EXTRA",
  "filePath": "docs/开发规范.md",
  "content": "# 开发规范",
  "syncEnabledFlag": true,
  "displayOrder": 100
}
```

### 3.1.4 更新项目 Markdown 文件

- 方法：`PUT`
- 路径：`/api/projects/{projectCode}/markdown-files/{fileId}`

核心请求字段：

- `content`
- `syncEnabledFlag`
- `displayOrder`

### 3.1.5 删除项目 Markdown 文件

- 方法：`DELETE`
- 路径：`/api/projects/{projectCode}/markdown-files/{fileId}`

说明：

- 基础文件建议只允许清空内容或禁用同步，不建议物理删除
- 额外文件允许删除

### 3.1.6 更新项目 Markdown 同步策略

- 方法：`PUT`
- 路径：`/api/projects/{projectCode}/markdown-policy`

核心请求字段：

- `markdownSyncMode`，必填

请求示例：

```json
{
  "markdownSyncMode": "CANCEL"
}
```

### 3.1.7 查询 Markdown 冲突记录

- 方法：`GET`
- 路径：`/api/projects/{projectCode}/markdown-sync-conflicts`

可选查询参数：

- `clientCode`
- `resolvedFlag`

核心响应字段：

- `projectCode`
- `clientCode`
- `filePath`
- `syncMode`
- `conflictReason`
- `resolvedFlag`
- `createdAt`

## 3.6 WebSocket 消息协议

### 3.6.0 WebSocket 建连说明

- 协议：`ws` / `wss`
- 地址：`/ws/clients/connect`
- 建议握手参数：
  - `clientCode`
  - `timestamp`
  - `sign` 或 `token`

说明：

- 首批二期优先使用原生 WebSocket，不强制引入 STOMP
- 消息体统一使用 JSON 文本帧
- 服务端应支持断线重连后的连接替换

## 3.6.1 `CLIENT_REGISTER`

方向：

- 客户端 -> 服务端

用途：

- 客户端首次建立 WebSocket 连接后注册自身信息

`payload` 示例：

```json
{
  "clientName": "Mac Mini 开发机",
  "osType": "MAC",
  "hostName": "mac-mini.local",
  "ipAddress": "192.168.31.10",
  "supportedAgentTypes": ["CODEX_CLI", "QODER_CLI", "CLAUDE_CODE"],
  "appVersion": "0.2.0"
}
```

## 3.6.2 `CLIENT_HEARTBEAT`

方向：

- 客户端 -> 服务端

用途：

- 维持在线状态

`payload` 示例：

```json
{
  "status": "ONLINE",
  "activeSessionCount": 2,
  "runningDispatchCount": 1
}
```

## 3.6.3 `CLIENT_AGENT_REPORT`

方向：

- 客户端 -> 服务端

用途：

- 上报本机 Agent 运行时能力

`payload` 示例：

```json
{
  "agentRuntimes": [
    {
      "agentType": "CODEX_CLI",
      "agentName": "Codex CLI",
      "agentVersion": "1.0.0",
      "commandPath": "/usr/local/bin/codex",
      "availableFlag": true,
      "capabilityTags": ["java", "spring", "docs"],
      "supportsSessionReuse": true
    }
  ]
}
```

## 3.6.4 `TASK_DISPATCH`

方向：

- 服务端 -> 客户端

用途：

- 主动下发任务

`payload` 示例：

```json
{
  "dispatchNo": "DISP-20260507-0001",
  "projectCode": "AI-PLATFORM",
  "requirementNo": "REQ-20260507-S-002",
  "rootRequirementNo": "REQ-20260507-M-001",
  "agentCode": "codex-cli-agent",
  "sessionStrategy": "REUSE_SELECTED",
  "sessionCode": "SES-20260507-001",
  "needSyncMarkdown": true,
  "taskPayload": {
    "title": "实现 WebSocket 客户端注册",
    "instruction": "完成客户端注册与心跳模块"
  }
}
```

## 3.6.5 `TASK_ACK`

方向：

- 客户端 -> 服务端

用途：

- 确认是否接收该任务

`payload` 示例：

```json
{
  "dispatchNo": "DISP-20260507-0001",
  "accepted": true,
  "message": "task accepted"
}
```

## 3.6.6 `TASK_PROGRESS`

方向：

- 客户端 -> 服务端

用途：

- 上报执行过程中的状态变化

`payload` 示例：

```json
{
  "dispatchNo": "DISP-20260507-0001",
  "status": "RUNNING",
  "progressPercent": 40,
  "message": "markdown sync completed"
}
```

## 3.6.7 `TASK_RESULT`

方向：

- 客户端 -> 服务端

用途：

- 回传最终执行结果

`payload` 示例：

```json
{
  "dispatchNo": "DISP-20260507-0001",
  "status": "SUCCESS",
  "resultSummary": "client register module completed",
  "deliverablePath": "client/register.py"
}
```

## 3.6.8 `ERROR_REPORT`

方向：

- 客户端 -> 服务端

用途：

- 上报异常，例如会话复用失败、Markdown 同步冲突、CLI 启动失败

`payload` 示例：

```json
{
  "dispatchNo": "DISP-20260507-0001",
  "errorType": "MARKDOWN_SYNC_CONFLICT",
  "message": "AGENTS.md local content conflicts with server copy"
}
```
