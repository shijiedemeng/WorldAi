# AI API 项目一期需求说明

## 1. 项目目标

建设一个基于 **Java Spring Boot** 的多 Agent 协同后端项目，核心目标是把：

- 会话通知
- 需求分发
- 开发执行步骤
- 测试状态
- Agent 协作结果汇总
- 主控 Agent 的缺口检查与二次派发

统一收敛到一套 **API + 数据表** 体系里，让主控 Agent 和各子 Agent 都通过接口驱动协作，而不是靠临时消息和人工追踪。

---

## 2. 业务定位

这个项目本质上是一个 **Agent 协同任务中台**。

### 2.1 主控 Agent职责

主控 Agent 负责：

- 创建项目资料
- 创建需求编号
- 拆分需求任务
- 指定哪个 Agent 负责哪个环节
- 跟踪开发链路是否完整
- 汇总各 Agent 回传结果
- 根据需求编号检查缺失项
- 对未完成环节再次通知指定 Agent

### 2.2 子 Agent职责

子 Agent 负责：

- 根据自己的 agent 标识拉取待办任务
- 更新任务进度
- 回传开发结果/测试结果/说明
- 标记是否阻塞、是否完成、是否需要协助

---

## 3. 一期范围

一期先解决“能跑起来”的最小闭环，不追求一步到位。

### 3.1 一期必须具备

1. 项目表
2. 需求编号表
3. 需求链路开发表
4. 测试表
5. Agent 表
6. 基础 API
7. 主控检查需求缺失项的能力
8. Agent 按身份拉取任务并回传结果的能力
9. 项目级 Markdown 文件管理与同步策略

### 3.2 一期暂不做

1. 复杂权限系统
2. IM/聊天平台直连
3. 工作流可视化页面
4. 自动代码执行沙箱
5. LLM 推理能力内置
6. 复杂审批流

---

## 4. 核心业务对象设计

## 4.1 项目表 `project_info`

用于让 AI/Agent 理解“这是个什么项目、用了什么技术、目标是什么”。

### 建议字段

- `id`：主键
- `project_code`：项目编码
- `project_name`：项目名称
- `project_desc`：项目说明
- `business_goal`：业务目标
- `tech_stack`：技术栈（JSON/文本）
- `repository_url`：代码仓库地址
- `owner_agent_code`：主控 Agent 标识
- `markdown_sync_mode`：Markdown 冲突策略（覆盖 / 冲突取消）
- `status`：状态（启用/停用）
- `created_at`
- `updated_at`

### 作用

- 让后续需求绑定项目
- 让 Agent 理解这个项目使用了哪些技术
- 让主控 Agent 有统一项目上下文
- 让不同电脑上的同项目基础 Markdown 保持一致

## 4.1.1 项目 Markdown 文件表 `project_markdown_file`

用于统一收口项目的基础 Markdown 和额外 Markdown 文件，供 Agent 按项目同步。

### 建议字段

- `id`
- `project_code`
- `file_type`：`BASE` / `EXTRA`
- `base_key`：基础文件槽位，可空
- `file_path`：相对路径
- `content`
- `created_at`
- `updated_at`

### 作用

- 统一项目基础 Markdown
- 支持项目额外补充文档
- 结合同步策略决定本地冲突时覆盖还是取消

---

## 4.2 需求编号表 `requirement_info`

用于管理需求主单。

### 建议字段

- `id`
- `requirement_no`：需求编号
- `project_code`：所属项目编码
- `title`：需求标题
- `requirement_desc`：需求说明
- `priority`：优先级
- `status`：状态（待分发/开发中/测试中/已完成/已阻塞）
- `source`：来源
- `main_agent_code`：主控 Agent
- `current_stage`：当前阶段
- `expected_deadline`：期望完成时间
- `created_by`
- `created_at`
- `updated_at`

### 作用

- 作为所有任务、测试、汇总的主关联键
- 主控 Agent 后续按 `requirement_no` 进行检查和催办

---

## 4.3 需求链路开发表 `requirement_dev_link`

这是核心表，用于描述一个需求被拆成哪些开发链路、由谁负责、当前执行到哪一步。

### 建议字段

- `id`
- `requirement_no`
- `link_type`：链路类型
  - backend
  - frontend
  - api
  - db
  - test
  - docs
  - deployment
  - review
- `task_title`：任务标题
- `task_desc`：任务描述
- `agent_code`：负责的 Agent
- `developer_name`：负责人/开发者名称
- `status`：待处理/处理中/已完成/阻塞
- `result_summary`：结果摘要
- `deliverable_path`：交付物路径/链接
- `depends_on_link_id`：依赖链路ID
- `started_at`
- `finished_at`
- `created_at`
- `updated_at`

### 作用

- 让主控 Agent 知道一个需求拆成了哪些部分
- 让子 Agent 知道自己该做什么
- 支撑缺失检查：比如少了 test、docs、db 变更说明等

---

## 4.4 测试表 `requirement_test_record`

用于记录测试计划、测试结果、问题和回归状态。

### 建议字段

- `id`
- `requirement_no`
- `test_type`：单元测试/接口测试/集成测试/人工测试/回归测试
- `test_title`
- `test_content`
- `tester_agent_code`
- `tester_name`
- `test_result`：通过/失败/阻塞
- `bug_count`
- `risk_desc`
- `suggestion`
- `attachments`
- `tested_at`
- `created_at`
- `updated_at`

### 作用

- 统一收口测试结论
- 让主控 Agent 可以知道需求是否真正闭环

---

## 4.5 Agent表 `agent_info`

用于登记系统里的所有 Agent，包括主控 Agent 和执行 Agent。

### 建议字段

- `id`
- `agent_code`：Agent 唯一标识
- `agent_name`
- `agent_role`：main / developer / tester / reviewer / ops
- `agent_desc`
- `capability_tags`：能力标签（JSON）
- `supported_link_types`：支持的链路类型（JSON）
- `callback_mode`：主动回传/轮询拉取
- `endpoint_url`：Agent 对应接口地址（如有）
- `status`：在线/离线/禁用
- `last_heartbeat_time`
- `created_at`
- `updated_at`

### 作用

- 管理所有 Agent 身份
- 支撑后续的分派和能力匹配

---

## 5. 关键流程设计

## 5.1 流程一：主控创建需求

1. 主控 Agent 创建项目资料（如项目不存在）
2. 主控 Agent 创建需求编号
3. 主控 Agent 拆分开发链路
4. 为每条链路指定 Agent
5. 系统生成子 Agent 待办任务

### 输出

- 需求主单
- 多条链路任务
- 可供 Agent 拉取的待办数据

---

## 5.2 流程二：子 Agent 拉取待办

1. 子 Agent 通过 `agent_code` 调用 API
2. 获取属于自己的待处理任务
3. 开始处理任务
4. 更新状态为处理中/已完成/阻塞
5. 回写结果摘要和交付物

---

## 5.3 流程三：主控检查缺失项

主控 Agent 输入需求编号后，系统自动检查：

- 是否存在 backend 链路
- 是否存在 frontend 链路（如该需求需要）
- 是否存在 api 链路
- 是否存在 db 链路
- 是否存在 test 记录
- 是否存在 docs 记录
- 是否所有关键链路都已完成
- 是否存在阻塞项未处理

### 输出

- 缺失项列表
- 未完成项列表
- 建议通知的 Agent 列表

---

## 5.4 流程四：主控二次通知对应 Agent

当主控检查到缺项时：

1. 按需求编号查询缺失链路
2. 找到负责该链路的 Agent 或可承担该链路的 Agent
3. 生成通知内容
4. 通过外部通知系统/消息系统发送给对应 Agent
5. 等待 Agent 回传更新

> 一期可以先只生成“待通知数据”，不强制集成真正消息渠道。

## 6. API 设计（一期草案）

## 6.1 项目管理

### 创建项目
- `POST /api/projects`

### 查询项目详情
- `GET /api/projects/{projectCode}`

### 项目列表
- `GET /api/projects`

---

## 6.2 需求管理

### 创建需求
- `POST /api/requirements`

### 查询需求详情
- `GET /api/requirements/{requirementNo}`

### 需求列表
- `GET /api/requirements`

### 更新需求状态
- `PUT /api/requirements/{requirementNo}/status`

---

## 6.3 需求链路开发管理

### 新增链路任务
- `POST /api/requirements/{requirementNo}/links`

### 查询需求下全部链路
- `GET /api/requirements/{requirementNo}/links`

### Agent 拉取自己的任务
- `GET /api/agents/{agentCode}/tasks`

### Agent 更新任务执行结果
- `PUT /api/links/{linkId}/progress`

---

## 6.4 测试管理

### 新增测试记录
- `POST /api/requirements/{requirementNo}/tests`

### 查询测试记录
- `GET /api/requirements/{requirementNo}/tests`

---

## 6.5 Agent 管理

### 注册 Agent
- `POST /api/agents`

### Agent 列表
- `GET /api/agents`

### Agent 详情
- `GET /api/agents/{agentCode}`

### 更新 Agent 心跳
- `POST /api/agents/{agentCode}/heartbeat`

---

## 6.6 主控检查接口

### 检查需求链路完整性
- `GET /api/requirements/{requirementNo}/inspection`

### 返回内容建议

- 需求基本信息
- 已存在链路
- 缺失链路
- 未完成链路
- 阻塞链路
- 建议通知 Agent 列表

---

## 7. 状态设计

## 7.1 需求状态

- PENDING：待分发
- IN_PROGRESS：开发中
- TESTING：测试中
- BLOCKED：阻塞
- DONE：已完成
- CLOSED：已关闭

## 7.2 链路任务状态

- TODO：待处理
- DOING：处理中
- DONE：已完成
- BLOCKED：阻塞
- SKIPPED：跳过

## 7.3 测试状态

- PASS：通过
- FAIL：失败
- BLOCKED：阻塞

## 7.4 Agent 状态

- ONLINE：在线
- OFFLINE：离线
- DISABLED：禁用

---

## 8. 一期主控检查规则

主控 Agent 可基于规则做最基础检查：

### 8.1 必查项

- 需求是否有至少一条开发链路
- 需求是否分配了负责 Agent
- 关键链路是否全部完成
- 是否存在至少一条测试记录
- 是否有阻塞状态未处理

### 8.2 可配置项

后续可引入项目级模板，比如：

- Java 后端项目默认必须包含：backend、api、test、docs
- 前后端分离项目默认必须包含：backend、frontend、api、test
- 数据变更需求默认必须包含：db、test、rollback-doc

---

## 9. 非功能需求

## 9.1 技术建议

- Spring Boot 3.x
- Spring Web
- Spring Validation
- Spring Data JPA / MyBatis Plus（二选一）
- MySQL 8.x
- Lombok
- MapStruct（可选）
- OpenAPI / Swagger

## 9.2 基本要求

- 接口统一返回结构
- 支持按需求编号快速查询
- 所有关键操作保留创建/更新时间
- 支持后续扩展通知模块
- 数据结构尽量避免绑死具体模型厂商

---

## 10. 一期接口返回统一结构建议

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

错误时：

```json
{
  "code": 500,
  "message": "error message",
  "data": null
}
```

---

## 11. 一期验收标准

满足以下条件即视为一期需求达标：

1. 可以创建项目
2. 可以创建需求编号
3. 可以为需求创建多个开发链路
4. 可以登记多个 Agent
5. Agent 能按 `agent_code` 拉取自己的待办
6. Agent 能更新任务执行结果
7. 可以登记测试记录
8. 主控能按需求编号检查缺项/未完成项/阻塞项
9. 能输出建议通知的 Agent 列表

---
